# Windows 与 Linux 新手部署指南设计

## 目标

为不了解代码、Docker 和 Linux 运维的使用者提供两条独立、可从零完成的操作路径：

1. 在 Windows 电脑上启动并使用 ONLYOFFICE 文档库。
2. 在 Ubuntu 22.04 或 24.04 服务器上部署并访问 ONLYOFFICE 文档库。

指南的成功标准不是“列出了完整命令”，而是读者能判断自己当前在哪一步、应在哪里操作、成功时会看到什么，以及失败后先检查什么。

## 文档结构

### README 首页

README 首屏使用普通语言说明项目用途，并提供三个明确入口：

- 我只想在 Windows 电脑上使用
- 我要部署到 Linux 服务器
- 我是开发或运维人员，需要完整技术资料

README 只保留最短的项目介绍和入口，不再要求新手先理解架构、端口、JWT 或 Compose 服务名。

### Windows 新手指南

新增 `docs/windows-beginner-guide.md`，按以下顺序组织：

1. 使用前准备：支持的 Windows 版本、内存和磁盘要求。
2. 安装并确认 Docker Desktop 正常运行。
3. 从 GitHub 下载 ZIP 并解压到固定位置。
4. 创建本机配置文件，并说明只需修改哪一项。
5. 在项目文件夹打开 PowerShell。
6. 启动服务，并解释第一次启动为什么需要等待。
7. 检查两个服务是否正常。
8. 打开文档库并完成第一次 Word/Excel 操作。
9. 日常启动、停止和重新启动。
10. 更新项目与保留已有文档。
11. 常见问题：Docker 未启动、端口占用、网页打不开、编辑器加载失败。

### Linux 新手指南

新增 `docs/linux-beginner-guide.md`，目标环境固定为 Ubuntu 22.04/24.04。按以下顺序组织：

1. 准备服务器：最低配置、系统版本、公网 IP 和安全组要求。
2. 使用 Windows Terminal 或服务器控制台连接服务器。
3. 安装 Docker，每次只给出当前步骤需要执行的一组命令。
4. 从 GitHub 下载项目到 `/opt/onlyoffice-demo`。
5. 创建配置文件，并区分“只用 IP 试运行”和“正式域名上线”。
6. 创建存储目录并设置权限。
7. 启动服务并等待健康检查。
8. 在浏览器中访问并完成第一次 Word/Excel 操作。
9. 配置云平台安全组和 Ubuntu 防火墙。
10. 日常启动、停止、查看状态和查看日志。
11. 上线前高级设置入口：域名、HTTPS、认证、备份恢复和回滚。
12. 常见问题与检查顺序。

原有 `docs/linux-deployment.md` 保留为高级运维手册，新手指南只在需要时链接到对应章节，不复制大段高级配置。

## 单步写作模板

每一个关键步骤统一包含以下内容：

1. **要做什么**：用一句话说明本步目标。
2. **在哪里操作**：明确是 GitHub 网页、Windows PowerShell、Docker Desktop、Linux 终端还是云平台控制台。
3. **具体操作**：先写点击路径，再提供一段可整体复制的命令。
4. **成功时看到什么**：给出界面文字、状态或返回结果。
5. **如果不成功**：只列本步骤最常见的两三个检查项，并链接到故障排查文档。

命令块前后必须有普通语言说明。不得连续堆叠多个用途不同的命令块，也不得要求读者自行推断占位符含义。

## 配置与安全表达

- 明确 `.env` 是本机或服务器配置文件，不需要提交到 GitHub。
- Windows 指南提供生成随机 `JWT_SECRET` 的可复制方法，避免要求用户手工编造。
- Linux 指南将 IP 试运行与域名 HTTPS 上线分开，避免第一次启动就引入 Nginx 和证书配置。
- 明确该演示没有用户登录和文件权限，不能未经认证直接暴露到互联网。
- 不在新手主流程中展开 SSRF、卷发现和原子恢复细节，只链接到高级运维手册。

## 验证要求

文档修改完成后执行以下检查：

1. README 中三个入口均能正确打开。
2. Windows 和 Linux 指南中的相对链接不存在失效路径。
3. 两条新手路径均能从空环境走到浏览器打开 `http://localhost:3000` 或服务器地址。
4. 每个关键步骤均包含操作位置和成功标志。
5. 命令、端口、环境变量和 Compose 服务名与项目实际配置一致。
6. 新手指南不会暗示 GitHub 可以直接运行后端服务。
7. 原高级部署文档继续保留 HTTPS、认证、备份、恢复和回滚内容。

## 范围边界

本次只改进文档导航和部署说明，不修改应用功能、Docker Compose 结构、端口、API 或存储格式。不会为特定云厂商编写专属购买流程，但会说明在任意云平台上需要确认的通用字段。
